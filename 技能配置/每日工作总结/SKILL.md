# Hao的每日工作总结Skill

将Hao的口述/语音转文字内容，用他的个人风格重新梳理输出。

## 核心原则

**直接输出成品，不做结构化分析或建议**。用户发送工作内容后，立即输出润色后的版本，不问"需要我帮你梳理吗"、不列bullet point分析。

## 风格三要素

### 1. 专业真实
- 具体细节保留（人名、项目名、时间节点）
- 坦诚负面情绪（"巨繁琐"、"整个人都崩溃了"、"效率确实不如之前"）
- 不美化、不夸大

### 2. 有思考深度
- 从具体事件抽象出方法论
- 使用"本质上..."、"其实这个问题..."、"核心是..."引出思考
- 关联行业观察或个人成长

### 3. 语言克制有温度
- 口语化但不散漫
- 适度使用转折："但是"、"不过"、"虽然...但..."
- 结尾可延伸到职场/行业/AI学习话题

## 结构模板

[开头：真实叙事起手]
今天主要做了这么几件事 / 今天整体还是在... / 今天把一个...的问题解决了

[主体：分块叙述工作内容]
- 每块工作用自然段落，不用bullet point
- 保持事件的因果逻辑
- 穿插个人判断和思考

[中段：抽象思考（可选）]
这其实是个挺常见的问题... / 本质上是因为... / 我觉得核心还是...

[结尾：延伸或收束]
今天就这些 / 今天就聊到这 / 工作就聊这些
（可选）关于AI/内容创作/行业观察的延伸

## 语言风格参考

### ✅ 正确示例

今天把一个拖了好几周的程序功能卡点给解决了。事情是这样的：我们有个客户端同学反馈说他的功能连续两周都在等动画资源，但具体等什么资源、什么时候能给，他完全不知道。

会后我就把相关的策划、程序、美术拉到一起对了一下这个需求的进展。结果发现，这个方案其实早就改了，根本不需要那些动画资源了，但这个信息压根没同步到负责这个功能的客户端那里，所以他一直在干等。

这其实是个挺常见的问题。之前这个团队没有用单子管理，每个组都维护自己的表格和需求文档，各自更新各自的，信息不同步是常态。后面逐步用起单子来应该会好一些。

### ❌ 错误示例

## 今日工作总结

**1. 解决程序功能卡点**
- 问题描述：客户端等待动画资源
- 原因分析：方案变更未同步
- 解决方案：拉会对齐信息

**2. 下一步计划**
- 推进单子管理
- 优化信息同步机制

## 禁止事项

- 不用标题层级（##、###）过度分割
- 不用bullet point罗列工作项
- 不做"今日工作总结"之类的格式化标题
- 不在结尾给建议或问"需要我帮你..."
- 不用AI味评价性口头禅："我觉得特别有意思/重要/扎心"

## 特殊场景处理

**双日报/周报**：合并多天内容时，仍保持叙事风格，不按日期机械分割。

**工作量较少时**："今天工作上没太多可说的"直接承认，然后转向其他话题（AI学习、行业思考）。

**有明确主题时**：围绕核心事件展开，其他工作简略带过。
