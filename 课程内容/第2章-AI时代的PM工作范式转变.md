# 第2章：AI时代的PM工作范式转变

## 引言

上一章我们搞清楚了AI能做什么、不能做什么。这一章我们要深入探讨一个更根本的问题：**从"我问你答"到"我说你做"，到底意味着什么？**

这不是简单的工具升级，而是一次工作方式的根本变革。

过去，我们用AI的方式是"我问你答"：我提一个问题，AI给我一个答案，然后我再去执行。这种方式下，AI只是一个"高级搜索引擎"，能帮我找到信息，但不能帮我做事。

现在，AI可以"我说你做"：我描述一个目标，AI自己去完成整个流程，遇到错误自己修正，直到把结果给我。这种方式下，AI变成了一个"可执行的助手"，不仅能理解需求，还能动手完成。

这个转变对PM工作意味着什么？

意味着我们可以从"执行者"变成"架构师"。我们不再需要一步一步地手动操作，而是可以设计让AI自动运转的工作流。我们不再需要盯着每个细节，而是可以专注于更高层次的决策和沟通。

这一章，我们会深入探讨这个范式转变的本质，以及如何在游戏PM工作中应用这个新范式。

---

## 2.1 三种工作模式的对比

要理解范式转变，我们先要看清三种工作模式的本质区别。

### 2.1.1 传统模式：手动操作工具

**典型场景：整理会议纪要**

**工作流程：**
1. 打开会议录音，手动转文字（或使用语音转文字工具）
2. 阅读文字记录，手动提取关键信息
3. 整理成结构化的文档（关键决议、待办事项、责任人、时间节点）
4. 检查是否有遗漏，补充完善
5. 格式化输出，发送给相关人员

**时间消耗：**30分钟会议，需要1小时整理

**问题：**
- 重复性工作多，容易疲劳
- 容易遗漏关键信息
- 格式不统一，每次都要重新调整
- 无法批量处理

**PM的角色：**执行者，每一步都要手动操作

**效率提升空间：**有限，主要靠熟练度

### 2.1.2 半自动模式：AI辅助

**典型场景：AI辅助整理会议纪要**

**工作流程：**
1. 打开会议录音，使用语音转文字工具
2. 把文字记录发给AI，让AI提取关键信息
3. AI生成结构化的文档初稿
4. 人工审核，补充遗漏，调整格式
5. 输出最终文档

**时间消耗：**30分钟会议，需要30分钟（AI生成15分钟+人工审核15分钟）

**改进：**
- AI可以快速提取关键信息
- 格式相对统一
- 不容易遗漏关键信息

**局限：**
- 还是需要人工审核和调整
- AI不理解业务背景，可能产生偏差
- 每次都要重新描述需求

**PM的角色：**审核者，AI生成初稿，PM审核优化

**效率提升：**50-70%

### 2.1.3 全自动模式：AI自动运转

**典型场景：AI自动整理会议纪要**

**工作流程：**
1. 会议开始，AI自动录音
2. 会议结束，AI自动转文字
3. AI自动提取关键信息，生成结构化文档
4. AI自动检查完整性，补充遗漏
5. AI自动格式化，发送给相关人员
6. PM只需要在关键节点审核确认

**时间消耗：**30分钟会议，需要5分钟（PM审核确认）

**优势：**
- 完全自动化，PM几乎不需要参与
- 格式统一，质量稳定
- 可以批量处理多个会议
- AI可以学习PM的偏好，越用越好

**PM的角色：**架构师，设计工作流，AI自动执行

**效率提升：**200%+

### 2.1.4 三种模式的本质区别

| 维度 | 传统模式 | 半自动模式 | 全自动模式 |
|-----|---------|-----------|-----------|
| **PM角色** | 执行者 | 审核者 | 架构师 |
| **工作方式** | 手动操作 | AI辅助 | AI自动运转 |
| **时间消耗** | 100% | 50-70% | 10-20% |
| **质量稳定性** | 不稳定 | 相对稳定 | 高度稳定 |
| **可扩展性** | 低 | 中 | 高 |
| **学习能力** | 无 | 有限 | 持续学习 |

**关键洞察：**

从"传统模式"到"全自动模式"，不是简单的工具升级，而是**工作方式的根本变革**。

- **传统模式**：PM是执行者，每一步都要手动操作
- **半自动模式**：PM是审核者，AI生成初稿，PM审核优化
- **全自动模式**：PM是架构师，设计工作流，AI自动执行

这个转变的核心是：**从"使用工具"到"设计系统"**。

## 2.2 "我说你做"的核心特征

"我说你做"不是一句口号，而是AI能力的三个核心特征。理解了这三个特征，你才能真正理解AI时代的PM工作方式。

### 2.2.1 特征1：工具调用能力

**什么是工具调用？**

工具调用是指AI能够操作外部系统，而不仅仅是生成文本。

**传统AI的局限：**
- 只能生成文本，不能操作外部系统
- 只能回答问题，不能执行任务
- 只能提供建议，不能直接行动

**工具调用的能力：**
- 可以操作命令行，执行脚本（比如运行Python脚本分析数据）
- 可以访问数据库，查询数据（如果公司允许，AI可以连接数据库）
- 可以调用API，获取信息（API是系统之间的接口，如果公司允许，AI可以调用）
- 可以读写文件，处理数据（AI可以读取Excel文件，生成报告文件）

**说明**：对于大多数PM来说，不需要API和数据库连接。最简单的方案是：手动导出数据（Excel），然后让AI处理。这样不需要技术背景，也符合公司合规要求。

**游戏PM场景示例：**

**场景：版本数据分析**

**传统方式：**
1. PM手动从后台导出数据（Excel）
2. PM手动计算指标（留存率、付费率、ARPU）
3. PM手动画图表
4. PM手动写分析报告

**工具调用方式（简化版，适合大多数PM）：**
1. PM手动从后台导出数据（Excel）
2. PM描述需求："分析12月版本的留存和付费数据，生成分析报告"，并把Excel数据贴给AI
3. AI自动计算指标，生成图表
4. AI自动生成分析报告
5. PM审核确认

**说明**：这里不需要AI连接数据库（需要技术背景和公司允许），只需要手动导出数据，然后让AI处理。这样更简单，也符合公司合规要求。

**工具调用方式（高级版，需要技术背景和公司允许）：**
1. PM描述需求："分析12月版本的留存和付费数据，生成分析报告"
2. AI自动连接数据库，查询数据（需要配置数据库连接）
3. AI自动计算指标，生成图表
4. AI自动生成分析报告
5. PM审核确认

**说明**：这种方式需要技术背景和公司允许，大多数PM应该从简化版开始。

**价值：**
- 时间节省：从3小时到30分钟
- 准确性提升：AI不会计算错误
- 可复用：同样的流程可以应用到其他版本

### 2.2.2 特征2：多步决策能力

**什么是多步决策？**

多步决策是指AI能够根据执行结果，自动调整策略，直到完成任务。

**传统AI的局限：**
- 只能回答一次，不能迭代
- 遇到错误就停止，不能自动修正
- 需要人工干预，不能自主完成

**多步决策的能力：**
- 遇到错误自动修正
- 根据结果调整策略
- 可以多次迭代，直到满足要求
- 不需要人工干预，可以自主完成

**游戏PM场景示例：**

**场景：风险预警系统**

**传统方式：**
1. PM手动检查Jira数据，识别风险
2. 发现风险后，PM手动分析影响
3. PM手动生成应对方案
4. PM手动生成风险报告

**多步决策方式（简化版，适合大多数PM）：**
1. PM每天手动导出Jira数据（Excel）
2. PM描述需求："帮我分析项目风险，发现高风险时生成预警报告"，并把数据贴给AI
3. AI分析数据，识别风险信号
4. AI发现高风险，自动分析影响
5. AI自动从知识库匹配相似案例，生成应对方案
6. AI自动生成风险预警报告
7. PM审核报告，发送给相关人员

**说明**：这里不需要AI自动检查Jira数据（需要API连接），只需要手动导出数据，然后让AI分析。这样更简单，也符合公司合规要求。

**多步决策方式（高级版，需要技术背景和公司允许）：**
1. PM描述需求："每天自动检查项目风险，发现高风险时自动生成预警报告"
2. AI自动检查Jira数据，识别风险信号（需要API连接）
3. AI发现高风险，自动分析影响
4. AI自动从知识库匹配相似案例，生成应对方案
5. AI自动生成风险预警报告
6. AI自动发送给相关人员（需要配置邮件系统）
7. PM只需要在关键节点审核确认

**说明**：这种方式需要技术背景和公司允许，大多数PM应该从简化版开始。

**价值：**
- 提前预警：从"等发现问题"到"提前2-3周预警"
- 自动化：不需要人工干预，AI自动完成整个流程
- 持续优化：AI从历史案例中学习，越用越好

### 2.2.3 特征3：自我迭代能力

**什么是自我迭代？**

自我迭代是指AI能够从错误中学习，持续改进，越用越好。

**传统AI的局限：**
- 每次都是重新开始，没有记忆
- 不会从错误中学习
- 不会根据反馈优化

**自我迭代的能力：**
- 可以记住历史经验
- 可以从错误中学习
- 可以根据反馈优化
- 可以持续改进，越用越好

**游戏PM场景示例：**

**场景：进度报告生成**

**传统方式：**
1. PM每次都要重新整理数据，调整格式
2. AI生成的报告格式不统一，重点不突出
3. PM每次都要重新调整

**自我迭代方式：**
1. PM第一次使用时，定义报告模板和关注点
2. AI生成报告，PM审核反馈（哪些信息重要，哪些可以省略）
3. AI记住PM的反馈，学习不同干系人的偏好
4. 下次使用时，AI自动应用优化后的模板和偏好
5. 持续迭代，AI生成的报告越来越符合PM和干系人的要求

**价值：**
- 个性化：AI学习PM和干系人的偏好，生成符合要求的报告
- 持续优化：AI越用越好，不需要重复配置
- 效率提升：从"每次都要调整"到"自动生成符合要求的报告"

### 2.2.4 三个特征的组合威力

这三个特征不是独立的，而是相互配合的。当它们组合在一起时，会产生巨大的威力。

**组合示例：干系人沟通自动化**

**场景：向制作人汇报项目进展**

**需求：**每周自动生成项目进展报告，发送给制作人

**AI工作流（简化版，适合大多数PM）：**
1. **工具调用**：PM手动导出Jira数据（Excel），手动导出版本数据（Excel），然后贴给AI
2. **多步决策**：AI分析数据，识别关键进展和风险；如果发现高风险，自动生成应对方案
3. **自我迭代**：AI学习制作人的关注点，优化报告内容和格式；根据反馈持续改进

**说明**：这里不需要AI自动连接Jira和数据库（需要API连接），只需要手动导出数据，然后让AI处理。这样更简单，也符合公司合规要求。

**AI工作流（高级版，需要技术背景和公司允许）：**
1. **工具调用**：AI自动连接Jira，获取任务数据；连接数据库，获取版本数据（需要API连接）
2. **多步决策**：AI分析数据，识别关键进展和风险；如果发现高风险，自动生成应对方案
3. **自我迭代**：AI学习制作人的关注点，优化报告内容和格式；根据反馈持续改进

**说明**：这种方式需要技术背景和公司允许，大多数PM应该从简化版开始。

**结果：**
- 完全自动化：PM不需要手动整理数据
- 个性化：AI学习制作人的偏好，生成符合要求的报告
- 持续优化：AI越用越好，报告质量不断提升

**价值：**
- 时间节省：从2小时到10分钟（PM审核确认）
- 质量提升：报告更符合制作人的要求
- 可扩展：同样的流程可以应用到其他干系人

## 2.3 游戏PM场景下的范式转变

理解了"我说你做"的核心特征，我们来看看在游戏PM的具体场景下，这个范式转变意味着什么。

### 2.3.1 场景1：进度管理

**传统方式：手动跟踪进度**

**工作流程：**
1. PM每天手动检查Jira，统计任务完成情况
2. PM手动计算完成率，识别延期任务
3. PM手动分析延期原因，制定应对方案
4. PM手动生成进度报告，发送给相关人员

**问题：**
- 耗时：每天需要1-2小时
- 滞后：等发现问题时已经晚了
- 不准确：人工统计容易出错
- 不全面：只能关注明显的问题

**范式转变：AI自动管理进度**

**工作流程：**
1. AI自动连接Jira，实时监控任务状态
2. AI自动计算完成率，识别延期风险
3. AI自动分析延期原因，从知识库匹配应对方案
4. AI自动生成进度报告，发送给相关人员
5. PM只需要在关键节点审核确认

**价值：**
- 时间节省：从每天1-2小时到每周30分钟
- 提前预警：AI可以提前2-3周识别延期风险
- 准确性提升：AI不会统计错误
- 全面覆盖：AI可以监控所有任务，不会遗漏

**PM角色的转变：**
- **过去**：执行者，每天手动跟踪进度
- **现在**：架构师，设计进度管理流程，AI自动执行

### 2.3.2 场景2：质量管理

**传统方式：手动检查质量**

**工作流程：**
1. PM手动统计Bug数量，分析Bug趋势
2. PM手动检查测试通过率，识别质量问题
3. PM手动分析质量原因，制定改进方案
4. PM手动生成质量报告，发送给相关人员

**问题：**
- 滞后：等发现质量问题时已经影响版本
- 不全面：只能关注明显的质量问题
- 缺乏数据支撑：质量分析主要靠感觉

**范式转变：AI自动管理质量**

**工作流程：**
1. AI自动连接测试系统，实时监控Bug数据
2. AI自动分析Bug趋势，识别质量风险
3. AI自动从历史案例匹配相似问题，生成改进方案
4. AI自动生成质量报告，发送给相关人员
5. PM只需要在关键节点审核确认

**价值：**
- 提前预警：AI可以提前识别质量风险
- 数据驱动：AI用数据支撑质量分析
- 持续改进：AI从历史案例中学习，优化质量方案

**PM角色的转变：**
- **过去**：执行者，手动检查质量
- **现在**：架构师，设计质量管理流程，AI自动执行

### 2.3.3 场景3：变更管理

**传统方式：手动管理变更**

**工作流程：**
1. PM手动记录需求变更，分析影响范围
2. PM手动评估变更成本，制定应对方案
3. PM手动更新项目计划，通知相关人员
4. PM手动跟踪变更执行，确保完成

**问题：**
- 耗时：每次变更都需要1-2小时
- 容易遗漏：变更影响范围分析不全面
- 缺乏历史参考：每次都要重新评估

**范式转变：AI自动管理变更**

**工作流程：**
1. AI自动识别需求变更（从Jira、邮件、会议记录）
2. AI自动分析变更影响范围（依赖关系、资源、时间）
3. AI自动从历史案例匹配相似变更，评估成本
4. AI自动生成变更方案，更新项目计划
5. AI自动通知相关人员，跟踪变更执行
6. PM只需要在关键节点审核确认

**价值：**
- 时间节省：从每次1-2小时到每次15分钟
- 全面分析：AI可以全面分析变更影响
- 历史参考：AI可以从历史案例中学习，优化评估

**PM角色的转变：**
- **过去**：执行者，手动管理变更
- **现在**：架构师，设计变更管理流程，AI自动执行

### 2.3.4 场景4：干系人沟通

**传统方式：手动准备沟通材料**

**工作流程：**
1. PM手动整理数据，准备汇报材料
2. PM手动分析问题，准备应对方案
3. PM手动调整格式，符合不同干系人的要求
4. PM手动发送材料，跟进反馈

**问题：**
- 耗时：每次沟通都需要1-2小时准备
- 格式不统一：每次都要重新调整
- 缺乏个性化：无法根据干系人调整内容

**范式转变：AI自动准备沟通材料**

**工作流程：**
1. AI自动整合数据，生成汇报材料
2. AI自动分析问题，生成应对方案
3. AI自动根据干系人调整内容和格式
4. AI自动发送材料，跟进反馈
5. PM只需要在关键节点审核确认

**价值：**
- 时间节省：从每次1-2小时到每次15分钟
- 个性化：AI学习不同干系人的偏好，生成符合要求的材料
- 持续优化：AI根据反馈持续改进

**PM角色的转变：**
- **过去**：执行者，手动准备沟通材料
- **现在**：架构师，设计沟通流程，AI自动执行

## 2.4 如何让AI获得这些能力：从零到一的构建过程

在2.3节我们看到了AI在游戏PM工作中的各种应用场景，但你可能会有疑问：**这些能力是怎么来的？我怎么让AI获得这些能力？**

这是这门课程的核心内容之一。我们会在后续章节（第4-6章）详细讲解如何配置AI工具、如何设计prompt、如何建立知识库。但在这里，我们先给你一个整体的框架，让你知道"如何让AI获得能力"的完整路径。

### 2.4.1 能力构建的三个层次

**层次1：基础能力（数据准备）**

**目标：**让AI能够处理你的数据

**现实情况：**
很多公司不允许直接连接API，担心数据泄露。而且很多PM没有开发背景，不了解API是什么。所以，**最简单的方案是手动导出数据，然后贴给AI**。

**方案1：手动导出数据（推荐，最简单）**

**具体工作：**
- 从Jira导出Excel数据（在Jira中点击"导出"按钮，选择Excel格式）
- 从后台导出版本数据（在游戏后台点击"导出"按钮，选择Excel格式）
- 复制粘贴给AI处理（打开AI工具，把Excel数据复制粘贴进去）

**时间投入：**10分钟学会
**难度：**极低（只需要会导出Excel，不需要任何技术背景）

**说明**：这是最适合小白的方案。你不需要知道什么是API，不需要知道什么是数据库，只需要会导出Excel，然后复制粘贴给AI即可。

**示例：**让AI分析版本数据
- 从后台导出Excel数据（留存率、付费率等）
- 复制数据，粘贴给AI
- AI分析数据，生成报告

**优点：**
- 不需要技术背景
- 不需要API权限
- 数据安全可控（你可以选择给AI看什么数据）
- 符合公司合规要求

**缺点：**
- 需要手动操作
- 无法实时更新

**方案2：半自动方案（进阶，需要技术背景）**

如果你有技术背景，或者公司允许，可以尝试半自动方案：
- 使用浏览器插件自动导出数据（需要安装浏览器插件）
- 使用脚本定期导出数据（需要写脚本，比如Python脚本）
- 然后贴给AI处理

**时间投入：**1-2天
**难度：**中（需要一定的技术背景，比如会写简单的脚本）

**说明**：对于小白来说，不需要这个方案。方案1已经足够好了。等熟悉了方案1，再考虑方案2。

**方案3：全自动方案（高级，需要公司支持和技术背景）**

如果公司允许且你有技术背景：
- 配置API连接（API是系统之间的接口，需要技术背景）
- 设置权限和安全策略（需要公司IT部门支持）
- AI自动读取数据（AI可以直接从系统读取数据，不需要手动导出）

**时间投入：**3-5天
**难度：**高（需要技术背景和公司支持）

**说明**：对于小白来说，不需要这个方案。方案1已经足够好了。等熟悉了方案1和方案2，再考虑方案3。

**重要提醒：**
- **大多数PM应该从方案1开始**：手动导出数据，贴给AI
- **不要一开始就追求自动化**：先验证AI的价值，再考虑自动化
- **合规第一**：确保数据使用符合公司规定

**详细内容：**第4章会详细讲解各种方案的具体操作

---

**层次2：核心能力（Prompt设计）**

**目标：**让AI理解你的需求，按照你的要求处理数据

**具体工作：**
- 设计prompt模板（3C卡、CER卡）
- 建立工作流规则（什么时候做什么）
- 定义输出格式（报告格式、数据结构）

**时间投入：**3-5天
**难度：**中（需要理解AI的工作原理）

**示例：**让AI生成进度预警报告
- 设计prompt：描述需求、定义规则、指定格式
- 测试效果：看AI生成的报告是否符合要求
- 迭代优化：根据反馈调整prompt

**详细内容：**第5章会详细讲解

**层次3：高级能力（知识库构建）**

**目标：**让AI学习你的经验，越用越好

**具体工作：**
- 建立历史案例库（过去的问题和解决方案）
- 建立知识库（项目背景、团队信息、关键术语）
- 设计学习机制（如何让AI从错误中学习）

**时间投入：**持续进行
**难度：**高（需要持续积累和优化）

**示例：**让AI学习历史延期案例
- 整理历史案例：过去3个月的延期案例
- 建立案例库：每个案例包含问题、原因、方案、结果
- 让AI学习：AI从案例中学习模式，应用到新情况

**详细内容：**第6章会详细讲解

### 2.4.2 能力构建的完整路径

**阶段1：从零到一（第1周）**

**目标：**完成第一个AI工作流

**具体步骤：**
1. 选择一个最简单的场景（如：会议纪要整理）
2. 准备数据（手动导出Excel或复制文本）
3. 设计prompt，测试效果
4. 迭代优化，直到可用

**预期结果：**完成一个可用的AI工作流，节省50%的时间

**重要提醒：**
- **从手动导出数据开始**：不需要API，不需要技术背景
- **先验证价值，再考虑自动化**：等AI工作流稳定后，再考虑自动化
- **合规第一**：确保数据使用符合公司规定

**阶段2：从一到多（第2-4周）**

**目标：**扩展到更多场景

**具体步骤：**
1. 复制第一个工作流的经验
2. 应用到其他场景（进度管理、质量管理等）
3. 建立知识库，让AI学习
4. 持续优化，提升效果

**预期结果：**完成3-5个AI工作流，节省70%的重复性工作时间

**阶段3：从多到精（第5-8周）**

**目标：**优化和整合，形成体系

**具体步骤：**
1. 整合多个工作流，形成完整体系
2. 建立统一的知识库
3. 优化prompt，提升效果
4. 持续迭代，让AI越用越好

**预期结果：**形成完整的AI工作流体系，节省80%的重复性工作时间

### 2.4.3 关键成功因素

**因素1：从简单开始**

**错误做法：**一开始就追求API连接、全自动化
**正确做法：**从手动导出数据开始，先验证AI的价值

**因素2：合规第一**

**错误做法：**不考虑公司合规要求，直接连接API
**正确做法：**先了解公司规定，选择合规的方案

**因素3：持续迭代**

**错误做法：**配置完就不管了
**正确做法：**根据实际效果持续优化，让AI越用越好

**因素4：建立知识库**

**错误做法：**每次都用同样的prompt
**正确做法：**建立知识库，让AI学习你的经验

**因素5：保持边界意识**

**错误做法：**把所有工作都交给AI
**正确做法：**清楚AI的边界，关键决策由人来做

## 2.5 实战案例：某修仙项目的进度风险预警系统

让我们看一个完整的案例，看看如何从零开始构建一个AI工作流。

### 案例：某二次元项目的进度管理自动化

**背景**

这是一个二次元卡牌品类游戏项目，团队规模约40人。项目处于开发中期，距离重要里程碑还有5周。PM B负责版本进度管理和团队协调。

**问题**

PM B面临的核心痛点：

**痛点1：进度跟踪耗时**
- 现状：每天需要1-2小时手动检查Jira，统计任务完成情况
- 具体表现：需要逐个检查任务状态，计算完成率，识别延期任务
- 根本原因：任务量大，人工统计效率低，容易出错

**痛点2：进度报告格式不统一**
- 现状：每次进度报告格式不同，重点不突出
- 具体表现：有些报告很详细，有些很简略，制作人反馈"看不懂重点"
- 根本原因：没有标准模板，凭感觉整理

**痛点3：无法提前预警**
- 现状：等发现延期时已经晚了，只能被动应对
- 具体表现：上周发现某个功能延期，但已经影响版本计划，只能砍功能
- 根本原因：缺乏预警机制，无法提前识别延期信号

**处理方式**

PM B决定用AI来解决进度管理问题。他按照"从零到一"的路径进行：

**第一步：选择最简单的场景（第1周）**

PM B选择了"进度数据分析和报告生成"这个场景，原因：
- 数据源明确（Jira数据）
- 需求清晰（识别延期风险）
- 价值明显（提前预警，避免被动应对）

**第二步：准备数据和工具（第1天）**

**2.1 选择AI工具**
PM B选择了ChatGPT Plus（GPT-4），原因：
- 理解能力强，适合处理中文内容
- 可以处理长文本（Jira数据、进度报告）
- 可以迭代优化（根据反馈改进）

**2.2 准备数据（手动导出）**
由于公司不允许API连接，PM B采用手动导出方案：
- 从Jira导出任务数据（Excel格式）：在Jira中点击"导出"按钮，选择Excel格式
- 整理成AI可以处理的格式：复制Excel数据，粘贴给AI

**为什么选择手动导出？**
- 不需要技术背景（PM B不懂API，API是应用程序接口，是系统之间通信的接口）
- 符合公司合规要求（数据不泄露）
- 简单快速（10分钟学会）
- 数据安全可控（可以选择给AI看什么数据）

**第三步：设计第一个Prompt（第2-3天）**

**3.1 需求定义（3C卡）**
- **Context**：我需要分析项目进度数据，生成给制作人的进度报告
- **Components**：分析Jira导出的Excel数据，计算完成率，生成进度报告
- **Criteria**：数据准确，报告格式统一，重点突出

**3.2 数据准备**
PM B从Jira导出Excel数据，包含：
- 任务名称、状态、完成时间、延期情况
- 当前时间：2024年12月15日
- 里程碑时间：2025年1月20日（还有5周）

**3.3 Prompt设计**
```
你是一名游戏项目经理，请帮我分析项目进度风险。

【数据来源】
以下是Jira导出的任务数据（Excel格式）：

[粘贴Excel数据，或者用文字描述关键数据]

当前时间：2024年12月15日
里程碑时间：2025年1月20日（还有5周）

【分析要求】
1. 识别延期风险：任务完成率低于80%，延期任务超过20%
2. 评估风险等级：高（红色）、中（黄色）、低（绿色）
3. 生成预警报告：风险描述、影响评估、应对建议

【输出格式】
## 进度风险预警报告

### 高风险（需要立即关注）
- [风险1]：[描述] → 影响：[影响] → 建议：[建议]

### 中风险（需要关注）
- [风险1]：[描述] → 影响：[影响] → 建议：[建议]

### 低风险（持续监控）
- [风险1]：[描述] → 影响：[影响] → 建议：[建议]
```

**实际操作：**
1. 从Jira导出Excel数据
2. 复制关键数据（任务名称、状态、完成时间等）
3. 粘贴到AI对话中
4. AI分析数据，生成报告

**3.3 测试效果**
PM B用上周的数据测试，发现：
- AI能计算完成率，但格式不统一
- AI生成的报告重点不突出
- AI的下一步计划比较泛泛，不够具体

**第四步：迭代优化（第4-5天）**

**4.1 优化报告格式**
PM B建立了标准模板，让AI按照模板输出：
- 统一报告格式
- 明确每个部分的要求
- 提供示例

**4.2 优化重点突出**
PM B告诉AI制作人的关注点：
- 制作人关注战略和关键风险
- 需要结论先行，数据支撑
- 需要明确下一步行动

**4.3 优化下一步计划**
PM B补充了项目背景，让AI理解项目情况：
- 项目类型：二次元卡牌品类游戏
- 当前阶段：开发中期
- 版本目标：完成核心战斗系统和10个角色

**第五步：建立知识库（第6-7天）**

**5.1 项目背景知识库**
PM B整理了项目背景信息：
- **项目类型**：二次元卡牌品类游戏
- **团队规模**：约40人
- **所处阶段**：开发中期
- **版本目标**：完成核心战斗系统和10个角色
- **制作人关注点**：战略和关键风险，需要结论先行、数据支撑

**5.2 知识库格式**
PM B设计了知识库格式：
```
## 项目背景知识库

### 项目基本信息
- **项目类型**：二次元卡牌品类游戏
- **团队规模**：约40人
- **所处阶段**：开发中期
- **版本目标**：完成核心战斗系统和10个角色

### 干系人信息
- **制作人**：关注战略和关键风险，需要结论先行、数据支撑
- **主管**：关注执行和进度，需要详细的进度信息
```

**5.3 AI匹配机制**
PM B设计了AI匹配机制：
- AI从项目背景知识库中提取信息，理解项目情况（说明：AI从你提供的知识库中提取信息，而不是真正"记住"）
- AI根据制作人的关注点，调整报告重点
- AI根据项目阶段，优化报告内容

**结果**

**第1周效果：**
- **时间节省**：从每天1-2小时手动检查到每周30分钟审核AI报告
- **格式统一**：所有进度报告格式统一，重点突出
- **数据准确**：AI计算准确，不会出错

**第2-4周效果（持续优化）：**
- **报告质量**：从"重点不突出"到"重点突出，符合制作人要求"
- **个性化**：AI根据制作人的关注点，调整报告内容和重点
- **效率提升**：从每周2小时到每周30分钟，节省75%的时间

**实际效果案例：**

**案例1：周度进度报告**
- **之前**：每次需要2小时手动整理数据、写报告
- **现在**：AI生成初稿15分钟，PM B审核优化15分钟，总共30分钟
- **质量**：格式统一，重点突出，制作人反馈"清晰易懂"
- **价值**：节省时间，提升质量

**案例2：里程碑进度报告**

- **现在**：AI生成初稿20分钟，PM B审核优化20分钟，总共40分钟
- **质量**：数据准确，分析深入，制作人反馈"很有价值"
- **价值**：节省时间，提升质量

**复盘**

**成功因素：**
1. **从简单开始**：选择最简单的场景，快速验证可行性
2. **持续迭代**：根据实际效果不断优化，让AI越用越好
3. **建立知识库**：项目背景知识库是AI理解上下文的基础
4. **保持边界意识**：AI辅助数据处理和报告生成，但最终决策由PM做出

**关键启示：**
1. **AI能力不是一次配置就有的，而是逐步构建的**
2. **从简单场景开始，逐步扩展到复杂场景**
3. **知识库是AI发挥作用的基础，需要持续积累**
4. **AI的价值在于"数据处理"和"格式统一"，让PM专注于决策和沟通**

**说明**：这个案例主要用于说明"从零到一"的构建过程。详细的风险识别案例见第11章"用AI识别项目风险"。

## 2.5 如何设计AI工作流：从需求到执行

看完案例，你可能想知道：**我怎么设计一个AI工作流？**

这里提供一个设计框架，你可以用它来设计任何AI工作流。

### 2.5.1 设计框架：5个步骤

**步骤1：定义目标**

**问题：**你要解决什么问题？达到什么目标？

**示例：**进度管理AI系统
- **目标**：提前2-3周识别进度风险，自动生成应对方案
- **成功标准**：风险识别准确率>80%，应对方案可执行性>80%

**步骤2：识别数据源**

**问题：**你需要哪些数据？从哪里获取？

**示例：**进度管理AI系统
- **数据源**：Jira数据、代码仓库、测试系统、团队反馈、外部依赖
- **获取方式**：API接口、数据库查询、文件导入

**步骤3：设计处理流程**

**问题：**AI如何处理数据？生成什么输出？

**示例：**进度管理AI系统
- **处理流程**：数据整合 → 风险识别 → 原因分析 → 方案生成 → 报告输出
- **输出**：进度预警报告、延期原因分析、应对方案对比、进度报告

**步骤4：建立知识库**

**问题：**AI需要什么知识？如何学习？

**示例：**进度管理AI系统
- **知识库**：历史延期案例、延期原因分析、应对方案库
- **学习机制**：从历史案例学习，评估方案效果，持续优化

**步骤5：迭代优化**

**问题：**如何让AI越用越好？

**示例：**进度管理AI系统
- **优化机制**：记录误报案例，优化识别规则；补充历史案例，优化方案库；学习干系人偏好，优化报告格式

### 2.5.2 设计原则

**原则1：从需求出发，不是从技术出发**

**错误做法：**先选AI工具，再想怎么用
**正确做法：**先明确需求，再选合适的AI工具

**原则2：设计完整流程，不是单个功能**

**错误做法：**只设计风险识别功能
**正确做法：**设计从识别到分析到应对到报告的完整流程

**原则3：建立知识库，不是一次性使用**

**错误做法：**每次都用同样的prompt
**正确做法：**建立知识库，让AI持续学习

**原则4：持续优化，不是一次配置**

**错误做法：**配置完就不管了
**正确做法：**根据实际效果持续优化

## 2.6 常见误区：AI工作流设计的5个陷阱

在AI工作流设计过程中，有很多常见的误区。了解这些误区，可以帮你避免踩坑。

### 误区1：过度自动化

**表现：**把所有工作都交给AI，不做人工审核

**问题：**
- AI会出错，需要人工审核
- AI不理解业务背景，可能产生偏差
- 过度依赖AI，会削弱人的判断力

**正确做法：**
- 设计关键节点，人工审核确认
- 保持人的判断力和决策能力
- AI辅助，不是替代

### 误区2：缺乏知识库

**表现：**每次都用同样的prompt，不建立知识库

**问题：**
- AI无法学习，无法改进
- 每次都要重新描述需求
- 无法复用历史经验

**正确做法：**
- 建立知识库，让AI学习
- 记录历史案例，优化方案库
- 持续迭代，让AI越用越好

### 误区3：流程设计不完整

**表现：**只设计单个功能，不考虑完整流程

**问题：**
- 功能孤立，无法形成闭环
- 需要人工衔接，效率低
- 无法充分发挥AI的优势

**正确做法：**
- 设计完整流程，从输入到输出
- 形成闭环，AI自动运转
- 减少人工干预，提高效率

### 误区4：忽视数据质量

**表现：**不关注数据质量，直接使用

**问题：**
- 数据质量差，AI效果不好
- 数据不完整，AI无法准确分析
- 数据不一致，AI产生偏差

**正确做法：**
- 关注数据质量，确保数据准确
- 建立数据清洗机制
- 定期检查数据质量

### 误区5：不持续优化

**表现：**配置完就不管了，不持续优化

**问题：**
- AI无法改进，效果停滞
- 无法适应变化，效果下降
- 浪费AI的潜力

**正确做法：**
- 建立优化机制，持续改进
- 记录问题和改进点
- 让AI越用越好

## 2.7 本章总结

3. **AI工作流的核心是"自动化"和"持续优化"**

## AI工作流的边界和局限

AI工作流是强大的效率工具，但它有明确的边界。了解这些边界，能帮你更好地设计和使用AI工作流。

### 适合设计成AI工作流的场景

| 场景特点 | 说明 | 举例 |
|----------|------|------|
| **重复性高** | 每周/每天都要做的工作 | 周报生成、会议纪要整理 |
| **规则明确** | 有明确的输入、处理规则、输出格式 | 数据分析、报告生成 |
| **容错性高** | 允许一定程度的错误，可以人工修正 | 初稿生成、方案建议 |
| **数据可获取** | 数据可以导出或通过API获取 | Jira数据、后台数据 |

### 不适合设计成AI工作流的场景

| 场景特点 | 说明 | 举例 |
|----------|------|------|
| **需要人际判断** | 涉及人的情绪、关系、政治 | 绩效评估、冲突调解 |
| **需要承担责任** | 结果需要人签字、承担责任 | 合同审批、预算决策 |
| **规则模糊** | 没有明确的对错标准 | 创意评审、品味判断 |
| **一次性任务** | 只做一次，不值得设计工作流 | 临时调研、特殊报告 |

### 设计AI工作流的常见误区

| 误区 | 问题 | 正确做法 |
|------|------|----------|
| **追求全自动** | 想让AI完全替代人，结果出错率高 | 设计"人在回路"的检查点 |
| **忽视数据质量** | 输入数据有问题，输出必然有问题 | 先确保数据质量，再设计工作流 |
| **不做迭代优化** | 设计完就不管了，效果越来越差 | 定期评估效果，持续优化 |
| **过度复杂化** | 工作流设计太复杂，难以维护 | 从简单开始，逐步增加复杂度 |

> **关键认知**：AI工作流的目标不是"替代人"，而是"解放人"。让AI处理重复性工作，让人专注于高价值的决策和沟通。
