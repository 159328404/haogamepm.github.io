# 第5章：你的方法论：双卡系统

## 引言

上周和一位PM朋友聊天，他说："我知道AI能帮我，但我每次让AI做事，结果都不对。要么是格式不对，要么是理解错了我的意思，要么是遗漏了关键信息。我试了几次就放弃了。"

这个问题很典型。很多PM知道AI有用，但不知道怎么让AI理解自己的需求。问题出在哪里？

不是AI不够强大，而是**我们不知道怎么把模糊的PM需求变成AI能理解的指令**。

这就像你和一个助手说话，你说"帮我整理一下会议记录"，助手可能理解成"把会议记录抄一遍"，而不是"提取关键决议和待办事项"。结果助手做了很多无用功，你也很挫败。

这一章，我们要解决的就是这个问题。我们会学习"双卡系统"——一套可复用的方法论，帮你把模糊的PM需求变成AI能理解的清晰指令，让AI在出错时自动修正，让AI越用越好。

这不是理论课，而是实战课。我们会用真实的游戏PM场景，让你看到如何用双卡系统解决实际问题。

## 5.1 为什么需要双卡系统：PM需求的特殊性

在深入双卡系统之前，我们先搞清楚一个问题：为什么PM的需求这么难让AI理解？

### 5.1.1 PM需求的三个特点

**特点1：需求模糊，边界不清**

**典型场景：**
- PM说："帮我分析一下项目风险"
- AI理解：分析什么风险？进度风险？质量风险？资源风险？分析到什么程度？输出什么格式？

**问题：**
- PM的需求往往是模糊的，边界不清
- AI不知道要做什么，做到什么程度
- 结果：AI要么做多了，要么做少了，要么做错了

**特点2：上下文复杂，信息分散**

**典型场景：**
- PM说："这个功能延期了"
- AI理解：什么功能？为什么延期？影响是什么？需要什么应对方案？

**问题：**
- PM的需求往往依赖复杂的上下文
- 信息散落在各种地方（Jira、邮件、会议记录、团队反馈）
- AI缺少必要的背景信息，无法准确理解

**特点3：标准不明确，因人而异**

**典型场景：**
- PM说："生成一份版本复盘报告"
- AI理解：报告给谁看？关注什么？格式要求是什么？详细程度如何？

**问题：**
- PM的需求标准往往不明确，因人而异
- 不同干系人关注点不同，报告要求不同
- AI不知道要符合什么标准

### 5.1.2 传统方式的局限

**方式1：直接下命令**

**示例：**
```
帮我整理一下会议记录
```

**问题：**
- 需求太模糊，AI理解有偏差
- 没有上下文，AI不知道项目背景
- 没有标准，AI不知道要做到什么程度
- 结果：AI生成的会议纪要格式不统一，遗漏关键信息

**方式2：详细描述需求**

**示例：**
```
帮我整理一下会议记录。这是一次项目评审会，参会人有制作人、主策、主程、主美和我。需要提取关键决议和待办事项，待办事项要有责任人和时间节点。格式要统一，不能遗漏关键信息。
```

**问题：**
- 每次都要重新描述，效率低
- 描述不系统，容易遗漏关键信息
- 没有结构化，AI理解不准确
- 结果：虽然比方式1好，但还是容易出错

**方式3：使用模板**

**示例：**
```
使用以下模板整理会议记录：
- 关键决议
- 待办事项（责任人、时间节点）
- 重要信息同步
- 遗留问题
```

**问题：**
- 模板是固定的，无法适应不同场景
- 没有上下文，AI不知道项目背景
- 没有标准，AI不知道要做到什么程度
- 结果：虽然格式统一了，但内容质量不稳定

### 5.1.3 双卡系统的价值

**双卡系统是什么：**

双卡系统是两套结构化的卡片模板：
- **3C卡（需求定义卡）**：帮你把模糊需求变成AI能理解的清晰指令
- **CER卡（问题诊断卡）**：帮你诊断AI的错误，快速修正

**双卡系统的价值：**

1. **结构化表达**：用固定的结构表达需求，AI理解更准确
2. **上下文完整**：强制提供必要的背景信息，AI理解更全面
3. **标准明确**：明确成功标准，AI知道要做到什么程度
4. **可复用**：一次设计，多次使用，效率更高
5. **可迭代**：出错时用CER卡诊断，快速修正

**关键洞察：**

PM的需求之所以难让AI理解，不是因为AI不够强大，而是因为**我们没有用AI能理解的方式表达需求**。双卡系统就是一套"翻译器"，帮你把模糊的PM需求翻译成AI能理解的清晰指令。

## 5.2 第一张卡：3C需求定义卡

3C卡是双卡系统的第一张卡，用于定义需求。它的核心逻辑是：**不要直接下命令，先填好这三个空**。

### 5.2.1 3C卡的结构

**3C卡包含三个部分：**

1. **Context（背景）**：我要做什么？目标是什么？给谁看的？
2. **Components（组件）**：这个任务包含哪些具体部分？
3. **Criteria（标准）**：有什么限制条件？成功标准是什么？

**3C卡的格式：**

```
【Context背景】
- 任务目标：[你要做什么]
- 使用场景：[在什么情况下使用]
- 目标受众：[给谁看的/用的]
- 项目背景：[项目类型、团队规模、所处阶段等]

【Components组件】
- 任务包含：[列出任务包含的具体部分]
- 输入数据：[需要什么数据]
- 输出格式：[输出什么格式]

【Criteria标准】
- 成功标准：[怎么算成功]
- 限制条件：[有什么限制]
- 质量要求：[质量要求是什么]
```

### 5.2.2 Context（背景）：让AI理解你的目标

**Context的作用：**

Context是3C卡的第一部分，作用是让AI理解你的目标。AI需要知道：
- 你要做什么？
- 在什么情况下使用？
- 给谁看的？
- 项目背景是什么？

**Context填写要点：**

1. **任务目标要明确**：不要说"帮我分析数据"，要说"分析12月版本的留存和付费数据，生成给制作人的分析报告"
2. **使用场景要具体**：不要说"项目评审"，要说"项目版本评审会，参会人有制作人、主策、主程、主美和我"
3. **目标受众要明确**：不要说"给领导看"，要说"给制作人看，他关注战略和关键风险"
4. **项目背景要完整**：提供项目类型、团队规模、所处阶段等关键信息

**游戏PM场景示例：**

**场景：让AI生成版本复盘报告**

**错误示例：**
```
帮我生成一份版本复盘报告
```

**正确示例（使用3C卡）：**
```
【Context背景】
- 任务目标：生成12月版本的进度分析报告，用于项目总结和改进
- 使用场景：版本封板后，需要向制作人汇报版本情况
- 目标受众：制作人，他关注战略和关键风险，需要数据支撑的观点
- 项目背景：
  - 项目类型：二次元卡牌品类游戏
  - 团队规模：约40人
  - 所处阶段：开发中期，刚完成12月版本封板
  - 版本目标：完成核心战斗系统和10个角色
```

**为什么Context重要：**

- **理解目标**：AI知道你要做什么，不会做错方向
- **理解场景**：AI知道在什么情况下使用，不会产生偏差
- **理解受众**：AI知道给谁看的，会调整内容和语气
- **理解背景**：AI知道项目背景，会提供更准确的建议

### 5.2.3 Components（组件）：让AI知道要做什么

**Components的作用：**

Components是3C卡的第二部分，作用是让AI知道要做什么。AI需要知道：
- 任务包含哪些具体部分？
- 需要什么输入数据？
- 输出什么格式？

**Components填写要点：**

1. **任务分解要完整**：把任务拆分成具体的部分，不要遗漏
2. **输入数据要明确**：明确需要什么数据，从哪里获取
3. **输出格式要具体**：明确输出什么格式，包含哪些内容

**游戏PM场景示例：**

**场景：让AI生成版本复盘报告**

**错误示例：**
```
生成版本复盘报告
```

**正确示例（使用3C卡）：**
```
【Components组件】
- 任务包含：
  1. 版本进度数据整理（任务完成率、延期率、Bug数等）
  2. 关键问题分析（识别版本中的关键问题）
  3. 改进建议（提供可执行的改进建议）
  4. 下一步计划（明确下个版本的重点）
- 输入数据：
  - 项目进度数据（从Jira导出，Excel格式）
  - 质量数据（从TAPD或测试系统导出，Excel格式）
  - 团队反馈（站会记录、1对1沟通记录）
- 输出格式：
  - Markdown格式
  - 包含：版本进度摘要、关键问题分析、改进建议、下一步计划
  - 每个部分要有数据支撑，不能有主观臆测
```

**为什么Components重要：**

- **任务完整**：AI知道要做什么，不会遗漏关键部分
- **输入明确**：AI知道需要什么数据，不会缺少信息
- **输出具体**：AI知道输出什么格式，不会格式混乱

### 5.2.4 Criteria（标准）：让AI知道要做到什么程度

**Criteria的作用：**

Criteria是3C卡的第三部分，作用是让AI知道要做到什么程度。AI需要知道：
- 怎么算成功？
- 有什么限制条件？
- 质量要求是什么？

**Criteria填写要点：**

1. **成功标准要可衡量**：不要说"质量要好"，要说"风险识别准确率>80%，报告格式统一"
2. **限制条件要明确**：明确有什么限制，比如"不能有主观臆测"、"必须用数据支撑观点"
3. **质量要求要具体**：明确质量要求，比如"格式要符合公司模板"、"信息要完整准确"

**游戏PM场景示例：**

**场景：让AI生成版本复盘报告**

**错误示例：**
```
生成一份好的版本复盘报告
```

**正确示例（使用3C卡）：**
```
【Criteria标准】
- 成功标准：
  1. 数据准确：所有数据必须与后台数据一致，不能有误差
  2. 分析深入：问题分析要有数据支撑，不能有主观臆测
  3. 建议可执行：改进建议要具体可执行，不能泛泛而谈
  4. 格式统一：格式要符合公司模板，不能随意发挥
- 限制条件：
  1. 不能有主观臆测：所有观点必须有数据支撑
  2. 不能遗漏关键信息：关键问题必须全部列出
  3. 不能过于详细：报告长度控制在3-5页，重点突出
- 质量要求：
  1. 格式要求：Markdown格式，使用公司标准模板
  2. 内容要求：结论先行，数据支撑，行动明确
  3. 语言要求：专业、简洁、可读性强
```

**为什么Criteria重要：**

- **标准明确**：AI知道要做到什么程度，不会做多或做少
- **限制清楚**：AI知道有什么限制，不会违反规则
- **质量保证**：AI知道质量要求，会生成符合要求的输出

## 5.3 第二张卡：CER问题诊断卡

CER卡是双卡系统的第二张卡，用于诊断AI的错误。它的核心逻辑是：**不要只说"不对"，要提供完整的错误现场**。

### 5.3.1 CER卡的结构

**CER卡包含三个部分：**

1. **Context（背景）**：我刚才让AI做什么？我的环境是什么？
2. **Error（错误）**：完整的错误信息是什么？或者你看到了什么不正常？
3. **Request（请求）**：我的期待是什么？我怀疑这是环境问题还是逻辑问题？

**CER卡的格式：**

```
【Context背景】
- 原始任务：[我刚才让AI做什么]
- 使用的Prompt：[我使用的完整prompt]
- 输入数据：[我提供了什么数据]
- 环境信息：[我的环境是什么]

【Error错误】
- 错误描述：[AI哪里出错了]
- 错误表现：[具体表现是什么]
- 错误信息：[如果有错误信息，粘贴完整错误信息]
- 预期结果：[我期望的结果是什么]
- 实际结果：[AI实际输出了什么]

【Request请求】
- 我的期待：[我希望AI做什么]
- 问题类型：[我怀疑这是环境问题还是逻辑问题]
- 需要帮助：[我需要什么帮助]
```

### 5.3.2 Context（背景）：让AI理解原始任务

**Context的作用：**

Context是CER卡的第一部分，作用是让AI理解原始任务。AI需要知道：
- 你刚才让AI做什么？
- 你使用的完整prompt是什么？
- 你提供了什么数据？
- 你的环境是什么？

**Context填写要点：**

1. **原始任务要完整**：不要只说"生成报告"，要说"生成12月版本的复盘报告，给制作人看"
2. **Prompt要完整**：粘贴你使用的完整prompt，不要省略
3. **输入数据要说明**：说明你提供了什么数据，数据来源是什么
4. **环境信息要完整**：说明你的环境，比如使用的AI工具、数据格式等

### 5.3.3 Error（错误）：让AI看到完整的错误现场

**Error的作用：**

Error是CER卡的第二部分，作用是让AI看到完整的错误现场。AI需要知道：
- 哪里出错了？
- 具体表现是什么？
- 如果有错误信息，完整的错误信息是什么？
- 你期望的结果是什么？
- AI实际输出了什么？

**Error填写要点：**

1. **错误描述要具体**：不要说"数据不对"，要说"AI说留存率是65%，但实际数据是58%，差了7个百分点"
2. **错误表现要详细**：详细描述错误的具体表现，不要泛泛而谈
3. **错误信息要完整**：如果有错误信息，粘贴完整的错误信息，不要省略
4. **对比要清晰**：明确对比预期结果和实际结果，让AI看到差异

- 每次都用同样的prompt

## 5.7 常见误区：双卡系统使用的5个陷阱

在双卡系统使用过程中，有很多常见的误区。了解这些误区，可以帮你避免踩坑。

### 误区1：3C卡填写不完整

**表现：**只填写Context，不填写Components和Criteria

**问题：**
- AI不知道要做什么，做到什么程度
- 结果不符合要求，需要多次迭代
- 效率低，质量不稳定

**正确做法：**
- 完整填写3C卡的所有部分
- Context、Components、Criteria都要填写
- 每个部分都要详细具体

### 误区2：CER卡描述不具体

**表现：**只说"不对"，不提供完整的错误现场

**问题：**
- AI不知道哪里出错了
- 无法诊断问题，无法修正错误
- 效率低，问题无法解决

**正确做法：**
- 详细描述错误的具体表现
- 对比预期结果和实际结果
- 提供完整的错误现场信息

### 误区3：不建立知识库

**表现：**每次都用同样的prompt，不建立知识库

**问题：**
- AI无法学习，无法改进
- 每次都要重新描述需求
- 无法复用历史经验

**正确做法：**
- 建立知识库，让AI学习经验
- 记录历史案例，优化方案库
- 持续迭代，让AI越用越好

### 误区4：不持续优化

**表现：**配置完就不管了，不持续优化

**问题：**
- AI无法改进，效果停滞
- 无法适应变化，效果下降
- 浪费AI的潜力

**正确做法：**
- 建立反馈循环，持续优化
- 记录问题和改进点
- 让AI越用越好

### 误区5：过度依赖AI

**表现：**把所有工作都交给AI，不做人工审核

**问题：**
- AI会出错，需要人工审核
- AI不理解业务背景，可能产生偏差
- 过度依赖AI，会削弱人的判断力

**正确做法：**
- 设计关键节点，人工审核确认
- 保持人的判断力和决策能力
- AI辅助，不是替代

   - Context（背景）：让AI理解原始任务
   - Error（错误）：让AI看到完整的错误现场
   - Request（请求）：让AI知道你需要什么帮助

4. **双卡系统的组合使用**
   - 用3C卡定义需求 → 用CER卡诊断问题 → 优化3C卡 → 重新使用
   - 形成迭代循环，让AI越用越好

5. **进阶技巧**
   - 建立3C卡模板库
   - 建立CER卡诊断库
   - 建立知识库，让AI学习经验
   - 建立反馈循环，持续优化

1. **PM的需求之所以难让AI理解，是因为我们没有用AI能理解的方式表达需求**
   - 双卡系统就是一套"翻译器"，帮你把模糊的PM需求翻译成AI能理解的清晰指令

   - 用3C卡定义需求 → 用CER卡诊断问题 → 优化3C卡 → 重新使用

### Prompt 1：用3C卡生成版本复盘报告

```
你是一名游戏项目经理，请帮我生成[版本名称]版本的复盘报告。

【Context背景】
- 任务目标：生成[版本名称]版本的复盘报告，用于项目总结和改进
- 使用场景：版本上线后，需要向制作人汇报版本情况
- 目标受众：制作人，他关注战略和关键风险，需要数据支撑的观点
- 项目背景：
  - 项目类型：二次元卡牌品类游戏
  - 团队规模：约40人
  - 所处阶段：开发中期，刚完成[版本名称]版本上线
  - 版本目标：[版本目标]

【Components组件】
- 任务包含：
  1. 版本数据整理（留存率、付费率、活跃度等）
  2. 关键问题分析（识别版本中的关键问题）
  3. 改进建议（提供可执行的改进建议）
  4. 下一步计划（明确下个版本的重点）
- 输入数据：
  - 版本数据（从后台导出，Excel格式）
  - 项目进度数据（从Jira导出，Excel格式）
  - 团队反馈（站会记录、1对1沟通记录）
- 输出格式：
  - Markdown格式
  - 包含：版本数据摘要、关键问题分析、改进建议、下一步计划
  - 每个部分要有数据支撑，不能有主观臆测

【Criteria标准】
- 成功标准：
  1. 数据准确：所有数据必须与后台数据一致，误差<1%
  2. 分析深入：问题分析要有数据支撑，不能有主观臆测
  3. 建议可执行：改进建议要具体可执行，不能泛泛而谈
  4. 格式统一：格式要符合公司模板，不能随意发挥
- 限制条件：
  1. 不能有主观臆测：所有观点必须有数据支撑
  2. 不能遗漏关键信息：关键问题必须全部列出
  3. 不能过于详细：报告长度控制在3-5页，重点突出
- 质量要求：
  1. 格式要求：Markdown格式，使用公司标准模板
  2. 内容要求：结论先行，数据支撑，行动明确
  3. 语言要求：专业、简洁、可读性强

【数据】
[粘贴版本数据、项目进度数据、团队反馈等]
```

## 双卡系统的边界和局限

双卡系统是一套实用的方法论，但它不是万能的。了解它的边界和局限，能帮你更好地使用它。

### 双卡系统适合什么场景？

| 适合场景 | 说明 | 举例 |
|----------|------|------|
| **信息处理类任务** | 输入是信息，输出也是信息 | 会议纪要、数据分析、报告生成 |
| **有明确标准的任务** | 能定义"什么是好的输出" | 格式化文档、数据提取、模板填充 |
| **可迭代的任务** | 允许多次尝试和优化 | 内部文档、分析报告、方案初稿 |

### 双卡系统不适合什么场景？

| 不适合场景 | 说明 | 替代方案 |
|------------|------|----------|
| **需要实时交互的任务** | 需要多轮对话、即时反馈 | 直接对话，不用填卡 |
| **标准模糊的创意任务** | 没有明确的"对错"标准 | 先用AI头脑风暴，再筛选 |
| **一次性简单任务** | 任务太简单，填卡比做任务还慢 | 直接下命令 |
| **涉及敏感决策的任务** | 需要人承担责任的决策 | AI辅助分析，人做决策 |

### 使用双卡系统的常见误区

| 误区 | 问题 | 正确做法 |
|------|------|----------|
| **填卡太详细** | 花太多时间填卡，效率反而降低 | 先简单填，不够再补充 |
| **填卡太简单** | 信息不够，AI理解不准确 | 至少填完三个C的核心内容 |
| **不迭代优化** | 用一次就放弃，不根据反馈优化 | 用CER卡分析错误，持续优化 |
| **过度依赖模板** | 机械套用模板，不根据场景调整 | 模板是起点，根据场景灵活调整 |

### Prompt工程的核心原则（AI工程师视角）

从AI工程师的视角，好的Prompt应该遵循以下原则：

1. **明确性原则**：AI需要明确知道"做什么"、"怎么做"、"做成什么样"
2. **完整性原则**：提供AI完成任务所需的所有信息，不要让AI猜
3. **可验证原则**：定义明确的成功标准，让你能判断AI的输出是否合格
4. **可迭代原则**：设计Prompt时考虑如何根据反馈优化

> **关键认知**：双卡系统不是"填表"，而是"思考框架"。它帮你系统地思考：我要什么？AI需要知道什么？怎么算成功？
