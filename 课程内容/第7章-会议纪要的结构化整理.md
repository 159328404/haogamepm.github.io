# 第7章：会议纪要的结构化整理

## 引言

上周和一位PM朋友聊天，他说："我每周要参加10多个会议，每次会议后都要整理会议纪要。30分钟的会议，整理纪要要1小时。最痛苦的是，会议记录里都是大段的文字，我要手动提取关键决议、待办事项、责任人、时间节点。每次整理完，眼睛都花了。"

这个问题太典型了。很多PM每天都要花大量时间整理会议纪要，但效果往往不理想：格式不统一、容易遗漏关键信息、无法快速查找历史决议。

这就像你有一个助手，他帮你记录会议，但记录的都是流水账。你需要的信息（关键决议、待办事项）都混在里面，你要花大量时间才能找到。

问题出在哪里？

不是会议记录不够详细，而是**我们没有把非结构化的会议记录转化成结构化的会议结论**。会议记录是"发生了什么"，会议结论是"要做什么"。PM需要的是后者，不是前者。

这一章，我们要解决的就是这个问题。我们会学习如何用AI把非结构化的会议记录转化成结构化的会议结论，如何提取关键信息，如何适配不同会议类型，如何让会议纪要成为可追溯、可执行的工作资产。

这不是理论课，而是实战课。我们会用真实的游戏PM场景，让你看到如何从零开始用AI整理会议纪要，如何让会议纪要成为你的得力助手。

## 7.1 会议纪要的痛点：为什么传统方式效率低

在深入AI解决方案之前，我们先搞清楚一个问题：为什么传统方式整理会议纪要效率这么低？

### 7.1.1 痛点1：信息提取耗时

**典型场景：**

某项目PM参加了一次30分钟的项目评审会，会议录音转文字后，有5000多字。这位PM需要从这5000字中提取：
- 关键决议：3个
- 待办事项：8个（每个都要有责任人、时间节点）
- 重要信息同步：5条
- 遗留问题：2个

**传统方式：**
1. 阅读5000字会议记录（10分钟）
2. 手动提取关键信息（30分钟）
3. 整理成结构化文档（15分钟）
4. 检查是否有遗漏（5分钟）

**总耗时：60分钟**

**问题：**
- 信息量大，阅读耗时
- 关键信息分散，提取困难
- 容易遗漏关键信息
- 格式不统一，每次都要重新调整

### 7.1.2 痛点2：格式不统一

**典型场景：**

某资深PM每周要整理10多个会议的纪要，但每次格式都不一样：
- 有些会议纪要很详细，有些很简略
- 有些有明确的待办事项，有些没有
- 有些有责任人，有些没有
- 有些有时间节点，有些没有

**问题：**
- 格式不统一，难以快速查找
- 信息不完整，无法追溯
- 无法批量处理，效率低
- 无法建立知识库，无法复用

### 7.1.3 痛点3：无法追溯历史决议

**典型场景：**

某PM想查找"3个月前关于美术资源延期的决议"，但会议纪要都是大段文字，无法快速查找。这位PM只能：
1. 回忆大概时间
2. 找到对应的会议纪要文件
3. 阅读大段文字，查找相关信息

**问题：**
- 无法快速查找历史决议
- 无法追溯决策过程
- 无法建立决策知识库
- 容易遗忘历史决议

### 7.1.4 痛点4：无法适配不同会议类型

**典型场景：**

某新人PM要整理不同类型的会议纪要：
- **项目评审会**：关注关键决议和风险
- **站会**：关注进度和阻塞
- **需求评审会**：关注需求确认和验收标准
- **复盘会**：关注问题和改进建议

每种会议类型关注点不同，但传统方式都是用同样的格式整理，导致信息不聚焦。

**问题：**
- 无法适配不同会议类型
- 信息不聚焦，重点不突出
- 无法建立会议类型知识库
- 无法复用会议模板

### 7.1.5 痛点总结

| 痛点 | 具体表现 | 影响 |
|-----|---------|------|
| **信息提取耗时** | 30分钟会议，整理纪要要1小时 | 效率低，时间浪费 |
| **格式不统一** | 每次格式不同，难以查找 | 无法建立知识库 |
| **无法追溯历史** | 无法快速查找历史决议 | 容易遗忘，无法复用 |
| **无法适配类型** | 不同会议类型用同样格式 | 信息不聚焦，重点不突出 |

**关键洞察：**

传统方式整理会议纪要的核心问题是：**把非结构化的会议记录当成最终交付物，而不是把结构化的会议结论当成最终交付物**。

会议记录是"发生了什么"，会议结论是"要做什么"。PM需要的是后者，不是前者。

## 7.2 AI解决方案：从会议记录到会议结论

理解了传统方式的痛点，接下来要学习如何用AI解决这些问题。

### 7.2.1 核心思路：结构化提取

**传统方式：**
- 输入：会议录音或文字记录（非结构化）
- 处理：人工阅读，手动提取
- 输出：会议纪要（半结构化）

**AI方式：**
- 输入：会议录音或文字记录（非结构化）
- 处理：AI理解内容，提取关键信息
- 输出：会议结论（结构化）

**结构化输出的格式：**

```markdown
# [会议主题] 会议结论
**时间**：[会议时间]
**参会人**：[参会人员]

## 关键决议
> 本次会议达成的核心共识和决定

- [决议1]
- [决议2]

## 待办事项
| 事项 | 责任人 | 截止时间 |
|------|--------|----------|
| [具体任务描述] | [人名] | [日期/待定] |

## 重要信息同步
> 会议中同步的关键信息、背景、数据等（如有）

- [信息点1]
- [信息点2]

## 遗留问题
> 未达成共识或需后续跟进的问题（如有）

- [问题1]：[简述分歧或待确认点]
```

### 7.2.2 关键能力：信息提取

**能力1：提取关键决议**

**什么是关键决议：**
- 会议中达成的共识
- 明确的决定和方向
- 需要执行的事项

**AI如何提取：**
- 识别决策性语言（"决定"、"同意"、"确定"等）
- 识别共识性表达（"大家一致认为"、"达成共识"等）
- 识别行动性语言（"要做"、"需要"、"必须"等）

**能力2：提取待办事项**

**什么是待办事项：**
- 具体的任务
- 有明确的责任人
- 有明确的时间节点（或"待定"）

**AI如何提取：**
- 识别任务性语言（"需要"、"要做"、"负责"等）
- 识别责任人（人名、角色）
- 识别时间节点（日期、时间、里程碑）

**能力3：提取重要信息**

**什么是重要信息：**
- 背景信息
- 数据信息
- 同步信息

**AI如何提取：**
- 识别信息性语言（"同步"、"告知"、"说明"等）
- 识别数据性内容（数字、百分比、指标等）
- 识别背景性内容（项目背景、历史情况等）

**能力4：识别遗留问题**

**什么是遗留问题：**
- 未达成共识的问题
- 需要后续跟进的问题
- 存在分歧的问题

**AI如何识别：**
- 识别分歧性语言（"有争议"、"未确定"、"待讨论"等）
- 识别不确定性表达（"可能"、"不确定"、"需要确认"等）
- 识别后续性语言（"后续跟进"、"待定"、"再讨论"等）

### 7.2.3 使用流程：从录音到结论

**流程1：准备会议记录**

**步骤1：获取会议录音或文字记录**
- 如果会议有录音：使用语音转文字工具（如讯飞、腾讯会议等）
- 如果会议有文字记录：直接使用
- 如果会议没有记录：会后尽快整理要点

**步骤2：整理会议信息**
- 会议主题
- 会议时间
- 参会人员
- 会议背景（可选）

**流程2：使用AI提取信息**

**步骤1：使用3C卡定义需求**

```
你是一名游戏项目经理，请帮我整理会议纪要。

【Context背景】
- 任务目标：将非结构化的会议记录转化成结构化的会议结论
- 使用场景：项目评审会，需要提取关键决议和待办事项
- 目标受众：项目团队成员，需要明确知道要做什么
- 项目背景：
  - 项目类型：二次元卡牌品类游戏
  - 团队规模：约40人
  - 所处阶段：开发中期

【Components组件】
- 任务包含：
  1. 提取关键决议（会议中达成的共识和决定）
  2. 提取待办事项（具体任务、责任人、时间节点）
  3. 提取重要信息同步（背景信息、数据信息）
  4. 识别遗留问题（未达成共识的问题）
- 输入数据：
  - 会议记录（文字记录或录音转文字）
  - 会议信息（主题、时间、参会人员）
- 输出格式：
  - Markdown格式
  - 包含：关键决议、待办事项、重要信息同步、遗留问题
  - 待办事项必须包含：事项、责任人、截止时间

【Criteria标准】
- 成功标准：
  1. 信息完整：所有关键决议和待办事项必须提取，不能遗漏
  2. 格式统一：按照标准格式输出，格式统一
  3. 责任明确：待办事项必须有明确的责任人，不能模糊
  4. 时间明确：待办事项必须有明确的时间节点（或"待定"），不能模糊
- 限制条件：
  1. 不能有主观臆测：所有信息必须来自会议记录，不能添加
  2. 不能遗漏关键信息：关键决议和待办事项必须全部提取
  3. 不能模糊表达：责任人、时间节点必须明确
- 质量要求：
  1. 格式要求：Markdown格式，使用标准模板
  2. 内容要求：结论先行，信息完整，行动明确
  3. 语言要求：专业、简洁、可读性强
```

**步骤2：提供会议记录**

```
【会议信息】
- 会议主题：12月版本评审会
- 会议时间：2024年12月15日 14:00-15:00
- 参会人员：制作人、主管、主策、主程、主美、PM

【会议记录】
[粘贴会议记录内容]
```

**步骤3：AI生成会议结论**

AI会生成结构化的会议结论，包含：
- 关键决议
- 待办事项（事项、责任人、时间节点）
- 重要信息同步
- 遗留问题

**流程3：审核和优化**

**步骤1：检查信息完整性**
- 关键决议是否完整？
- 待办事项是否完整？
- 责任人是否明确？
- 时间节点是否明确？

**步骤2：检查格式统一性**
- 格式是否符合标准？
- 信息是否清晰？
- 是否易于查找？

**步骤3：优化和补充**
- 补充遗漏的信息
- 优化模糊的表达
- 调整格式

### 7.2.4 效果对比

**传统方式：**
- 时间消耗：30分钟会议，整理纪要要60分钟
- 格式：不统一，每次都要调整
- 信息：容易遗漏，无法追溯
- 可复用性：低，无法建立知识库

**AI方式：**
- 时间消耗：30分钟会议，整理纪要要15分钟（AI生成10分钟+人工审核5分钟）
- 格式：统一，符合标准模板
- 信息：完整，可追溯
- 可复用性：高，可以建立知识库

**效率提升：75%**

**问题**

小陈面临的核心痛点：

**痛点1：整理会议纪要耗时**

## 7.5 常见误区：会议纪要整理的5个陷阱

在会议纪要整理过程中，有很多常见的误区。了解这些误区，可以帮你避免踩坑。

### 误区1：把会议记录当成会议结论

**表现：**直接把会议录音转文字的结果当成会议纪要

**问题：**
- 会议记录是"发生了什么"，会议结论是"要做什么"
- PM需要的是后者，不是前者
- 会议记录信息量大，难以快速查找

**正确做法：**
- **提取关键信息**：从会议记录中提取关键决议、待办事项、责任人、时间节点
- **结构化输出**：按照标准格式输出，便于查找和追溯
- **结论先行**：重点关注"要做什么"，而不是"发生了什么"

### 误区2：不明确责任人和时间节点

**表现：**待办事项的责任人写"团队"，时间节点写"尽快"

**问题：**
- 责任人不明确，无法执行
- 时间节点模糊，无法跟踪
- 容易遗忘，无法追溯

**正确做法：**
- **责任人明确**：必须是具体人名，不能是"团队"、"大家"等模糊表达
- **时间节点明确**：必须是具体日期（如"2024年12月20日"），或明确标注"待定"
- **不能模糊**：不能是"尽快"、"尽快完成"等模糊表达

### 误区3：不适配不同会议类型

**表现：**所有会议类型用同样格式整理

**问题：**
- 信息不聚焦，重点不突出
- 无法适配不同会议类型的特点
- 无法建立会议类型知识库

**正确做法：**
- **建立会议类型知识库**：让AI理解不同会议类型的特点和关注点
- **适配不同类型**：根据会议类型，调整提取策略和输出格式
- **建立模板库**：为不同会议类型建立标准模板

### 误区4：不建立知识库

**表现：**每次整理会议纪要，都要重新描述需求

**问题：**
- 效率低，每次都要重新描述
- 格式不统一，无法追溯历史
- 无法复用，无法建立知识库

**正确做法：**
- **建立知识库**：建立会议类型知识库、会议模板库
- **复用模板**：使用标准模板，确保格式统一
- **持续积累**：建立会议结论知识库，可以追溯历史

### 误区5：不审核AI输出

**表现：**完全依赖AI，不做人工审核

**问题：**
- AI会出错，需要人工审核
- AI可能遗漏关键信息
- AI可能理解错误

**正确做法：**
- **人工审核**：AI生成后，必须人工审核
- **检查完整性**：检查信息是否完整，格式是否正确
- **补充完善**：如有遗漏，及时补充完善
